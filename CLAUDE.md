## Project Overview

Salon management system (Velour). **React + TypeScript SPA** (`frontend/`) communicates with a **Python FastAPI backend** (repo root) over HTTP. State is persisted in SQLite (`velour.db`, generated by `seed.py`).

## Running the Project

Both services must run simultaneously.

**Python backend (start first):**
```bash
# From repo root (Windows)
.venv\Scripts\activate
python seed.py           # first run only — populates velour.db
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```
Swagger UI: http://127.0.0.1:8000/docs

**React frontend:**
```bash
cd frontend
npm install   # first run only
npm run dev   # http://localhost:5173
```

## Architecture

```
Browser ↔ React SPA (Vite, port 5173) ↔ FastAPI (Python, port 8000) ↔ SQLite (velour.db)
```

**Frontend** (`frontend/src/`):
- `api/client.ts` — all Axios calls grouped by domain; never call axios directly from pages
- `api/types.ts` — TypeScript types mirroring Pydantic schemas; keep in sync with backend enums
- `context/AuthContext.tsx` — JWT stored in localStorage; Axios interceptor adds Bearer header
- `pages/` — one file per route; no shared state store beyond AuthContext
- `components/` — Layout, Sidebar, Modal, TierBadge, StatusBadge, BriefingDrawer, Spinner

**Backend** (repo root):
- `routers/` — one router per domain (auth, users, clients, professionals, services, appointments, loyalty, referrals, dashboard, reports)
- `models/` — SQLAlchemy ORM models; `__init__.py` re-exports everything
- `schemas/` — Pydantic request/response schemas
- `auth.py` — JWT HS256 + PBKDF2; `get_current_user`, `require_admin` dependencies
- `birthday_scheduler.py` — APScheduler job at 08h, awards 100 pts on client birthday
- `seed.py` — populates velour.db with realistic dev data

## Key Domain Rules

- Appointment `ends_at` is computed server-side as `scheduled_at + service.duration_minutes`; never accepted from the client
- Conflict detection in `POST /appointments` rejects overlapping intervals for the same professional (HTTP 409); cancelled and no_show appointments are ignored
- `discount_points_used` must be a multiple of 100 (100 pts = R$10 discount, capped at 50% of price)
- Referral conversion fires automatically on the first completed appointment of a referred client
- Loyalty tier is recalculated on every completed appointment based on `client.total_spent`

## Enum Values (keep frontend and backend in sync)

| Concept | Backend (Python) | Frontend (TypeScript) |
|---|---|---|
| Gender | `M`, `F`, `other` | `'M'`, `'F'`, `'other'` |
| ChatPreference | `chatty`, `quiet`, `neutral` | `'chatty'`, `'quiet'`, `'neutral'` |
| AppointmentStatus | `scheduled`, `confirmed`, `in_progress`, `completed`, `cancelled`, `no_show` | same |
| LoyaltyTxType | `earned_appointment`, `earned_referral`, `earned_birthday`, `redeemed` | same |
| GenderTarget | `M`, `F`, `all` | `'M'`, `'F'`, `'all'` |

## Known Limitations

- `SECRET_KEY` and `DATABASE_URL` are hardcoded (not environment variables) — fine for dev, must change for production
- Frontend `baseURL` is hardcoded to `http://127.0.0.1:8000` in `api/client.ts`
- No rate limiting on auth endpoints
